# Let him calc
## Задание
Реализовать интерпретатор мини-языка выражений. Язык должен поддерживать арифметическое операции, сохранение значений в переменные в контексте одного вычисления.

Пример синтаксиса языка:  
```text
2 + 3 * 4
let x = 10 in x - 3
let x = 2 in let y = x * 5 in y + 1
(1 + 2) * 3
```

Минимальный состав компонентов итоговой программы:
1) Монада `Parser`
2) Описание структуры грамматики (дерево)
3) Разбор сырой строки в выражение
4) Модуль вычисления выражения
5) Точка входа в интерактивный режим языка
## 1. Монада Parser

Предлагается работать с такой сигнатурой. Вы можете её изменить/переименовать, если считаете предложенный вариант неудобным. Важно сохранить смысл: обертка над функциональной стрелкой, которая из строки позволяет получить текст ошибки разбора (Left), либо разобранное значение + остаток строки для разбора (Right)
```haskell
newtype Parser a = Parser {parse :: String -> Either String (a, String)}
```
В рамках работы над этим компонентом ожидается следующее:
* Сделать `Parser` представителем Monad (а также Functor, Applicative)
* Написать набор 'комбинаторов', который будет использован далее для разбора строк

Описание минимального набор комбинаторов (необязательно использовать предложенные наименования):
* `satisfy :: (Char -> Bool) -> Parser Char`
	* Принимает предикат. Если следующий символ в строке удовлетворяет этому предикату, то вычитывает его из разбираемой строки
	* Пример: использование предиката `isDigit` вернет `Right ('6', "8")` на входной строке `"68"`. Если исходная строка пуста / предикат не подходит ожидается `Left`
* `char :: Char -> Parser Char`
	* Принимает символ. Если следующий в строке символ ему равен, то вычитывает его из разбираемой строки. В ином случае возвращает `Left`
	* Пример: `char 'a'` для `"abc"` возвращает `Right ('a', "bc")`
* `string :: String -> Parser String`
	* Работает аналогично `char`, но принимает строку 
* `orElse :: Parser a -> Parser a -> Parser a`
	* Если вычисление в первом аргументе успешно - возвращает его же. Иначе, запускает вычисление, переданное во втором аргументе (на той же исходной строке)
* `many :: Parser a -> Parser [a]`
	* Повторяет один и тот же парсер, пока тот успешен
	* Пример: `many (char 'a')` для `"aab"` даёт `Right ("aa", "b")`

## 2. Expression и парсер
Описать ADT для описания выражения. У нашей грамматики довольно маленький алфавит
* числа
* ключевое слово `let`, `in`
* переменные, которые задаются при помощи `let`
* Арифметическое операции (сложение, вычитание, умножение, деление)
	* Деление является целочисленным
	* Не требуется поддерживать унарный минус


Описать функцию, выполняющую разбор строки в дерево выражений. Рекомендую писать эту функцию в несколько этапов
1. Научиться разбирать одно число
2. Научиться разбирать строку, которая состоит только из чисел и операций сложения и убирать незначащие пробелы. Пример строки:  `1 +2 + 3`
3. К предыдущему шагу добавить операцию умножения. Где-то тут вы научитесь разделять операции по приоритету
4. Научиться корректно читаться скобки и менять приоритет в зависимости от их расстановки
5. Научиться читать переменную и `let`
6. Теперь можно собрать итоговую функцию, которая будет иметь приблизительно такую сигнатуру `parseExpr :: String -> Either String Expr` 

На этом этапе вы можете добавить вспомогательные комбинаторы в `Parser`, чтобы использовать их при разборе в дерево.
## 3. Вычисление
Реализовать функцию, которая производит вычисление на основе дерева из предыдущего шага. Примерно ожидаемая сигнатура
```haskell
eval :: Expr -> Either String Integer
```
`Right` - выражение корректно, оборачивается результат вычисления. `Left` - выражение некорректно, оборачивается текст ошибки (деление на ноль/неизвестная переменная и т.п)

После реализации, у вас, вероятно, образуется некий ассоциативный список, с переменными. Подумайте, как применить тут `ReaderT`, чтобы явно не прокидывать список в каждый шаг
## 4. Точка входа

Точкой входа должен быть бесконечный цикл
* `:q` - команда, при которой цикл завершается
* При успешном вычислении выводится результат
* При неуспешном вычислении/разборе требуется вывести текст ошибки

## Ожидаемый Flow вычисления
Сырая строка из IO -> построение дерева выражений -> результат вычисления -> вывод в IO 
## Требования и примечания
* Архитектура. Ожидается разбиение программы на модули. Модули должны отделять логические части программы. Не должно получиться такого, что модуль с монадой `Parser`  знает о структуре синтаксического дерева и наоборот. 
* Модуль не должен экспортировать свои внутренние функции
* Если в результате разбора остался хвост, то требуется вернуть ошибку
* `let` действует только в контексте одного вычисления. Как только текущее вычисление заканчивается, то переменные и их значения заканчиваются
* `let` может быть вложен сам в себя. Вложенный `let` может иметь такое же имя переменной, как и родительский
	* `let x = 1 in (let x = 2 in x) + x` - пример валидного выражения, результат которого равен `3`
